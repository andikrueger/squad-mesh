## Analysis Output

Moe completed skeptical stress test of whether squad-holacracy's local-first architecture needs to become API-based.

**Key Findings:**
- No. Not yet. Not for Andi's 8 squads on one machine. Not for current use case.
- Context-hub solves *external library documentation* (vertical concern). Squad orchestration solves *cross-squad coordination* (horizontal concern). These are unrelated architecturally.
- Local-first breaks **if and only if** squads cannot share a filesystem. Today, they can. All 8 squads on `C:\dev` reachable via `fs.*`.
- Adding API contracts costs ~200-400 engineering hours (auth, service availability, schema versioning, testing, ops) for zero measurable benefit at 8 squads on 1 machine.

**YAGNI Analysis:**
- 5 out of 5 cross-squad capabilities (discovery, status, learning, directives, tensions) **Local wins** for current scale
- API adds latency, availability concerns, auth debt with zero functional benefit

**Failure Modes Identified:**
- Failure 1 (multi-machine squads): Not happening (all on C:\dev)
- Failure 2 (programmatic integration): Not needed (Andi uses CLI)
- Failure 3 (webhooks/events): Not required (manual tension management)
- Failure 4 (SDK evolution): Unknown (Squad SDK timeline unclear)
- Failure 5 (concurrent write safety): Possible but not reported; solvable via file locking first

**Technical Debt Identified:**
Real prep work is NOT building APIs now, but extracting ~40 raw `fs.*` calls behind an I/O abstraction layer. Makes APIs insertable later in ~4 hours.

**Verdict:** Keep local-first with evidence-based triggers for revisit:
- First squad on different machine → add registry-based remote discovery
- >15 squads → add indexed registry
- Concurrent write corruption reported → add file locking
- Squad SDK ships API contracts → adapt via abstraction layer
- Web dashboard requested → add read-only API

**Deliverables:**
- `architecture-review/moe-local-vs-api-contracts.md` — Full stress test
- `.squad/decisions/inbox/moe-api-contract-stance.md` — Decision proposal

**Recommendation:** Do not add API infrastructure now. Focus on extracting fs.* behind abstraction layer as technical debt prep work.
